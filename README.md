# ESP32 Lab — лаборатория микроконтроллеров в браузере

Учебный сайт для курса «Интернет вещей»: студенты собирают схемы, пишут код на Arduino C++ для ESP32, запускают его
в симуляторе прямо в браузере и проходят практики с автопроверкой. Преподаватель видит прогресс группы, проверяет
работы и ставит оценки. Готовый скетч можно скомпилировать настоящим `arduino-cli` и прошить в реальную плату по USB.

**Рабочий сайт:** <https://iot.quest-practices.ru>

## Возможности

* **Симулятор ESP32 в браузере.** Собственный транслятор Arduino C++ → JavaScript с семантикой C: целочисленное
  деление, переполнение `byte`, печать `float` с двумя знаками, `String`, массивы, struct/class, лямбды, ссылки,
  `#define`, прерывания, аппаратные таймеры, FreeRTOS (задачи, очереди, семафоры). Ошибки компиляции — на русском,
  с подсказками («Пропущена `;`», «Возможно, вы имели в виду `digitalWrite`?»). Аварии — как у настоящей платы
  (Guru Meditation при делении на ноль, выходе за границы массива, бесконечной рекурсии).
* **Электрическая модель схемы.** Узловой анализ: светодиоды без резистора перегреваются и сгорают, вход без подтяжки
  «висит», делитель напряжения даёт честные значения АЦП, реле коммутирует нагрузку, КЗ питания отключает плату,
  перегрузка вывода GPIO > 40 мА — предупреждение.
* **Редактор схем** с автоматической разводкой проводов: провода обходят детали, выходят из выводов
  перпендикулярно, не накладываются друг на друга, а GND и питание сходятся в общую шину с узлами.
  Экспорт схемы в Wokwi (`diagram.json`).
* **25 компонентов:** ESP32 DevKit V1, макетка, светодиоды, RGB, резисторы (с цветными полосками), кнопки (с дребезгом),
  переключатель, потенциометр, фоторезистор, пищалки, реле, вентилятор, лампа, электрозамок, сервопривод,
  DHT22/DHT11, HC-SR04, PIR, MQ-2, LCD 1602 I²C, OLED SSD1306, кольцо NeoPixel, логический анализатор,
  «чёрный ящик» UART и I²C-модуль с регистрами.
* **Библиотеки:** Serial/Serial2, Wire, SPI, WiFi, HTTPClient, WebServer, PubSubClient, ArduinoJson (v6 и v7),
  DHT, ESP32Servo, LiquidCrystal_I2C, Adafruit SSD1306 + GFX, Adafruit NeoPixel, Preferences, Ticker, LEDC (API ядер 2.x и 3.x).
* **Сеть:** виртуальные Wi-Fi-сети, учебные веб-сервисы (погода, чат, время, «центр управления станцией»),
  общий MQTT-брокер (Mosquitto, к нему подключаются и настоящие платы), встроенный браузер для веб-сервера ESP32.
* **Приборы:** монитор порта (с «каракулями» при неверной скорости), плоттер, логический анализатор с декодером UART,
  журнал сети, MQTT-клиент, чат.
* **Настоящая плата:** компиляция `arduino-cli` (ядро ESP32 2.0.17 — совместимо с кодом лекций) и прошивка через
  Web Serial (Chrome/Edge), монитор порта платы.
* **Курс:** 35 практик в 6 модулях по пяти лекциям — лабораторные, домашние (интереснее и сложнее лекций), кейсы и тесты,
  сквозной сюжет про арктическую станцию «Полярная-5», опыт, уровни и достижения.
* **Преподавателю:** группы с кодами, матрица прогресса, очередь работ на проверку, просмотр работы в верстаке,
  эталонное решение, оценки и комментарии, дедлайны, выгрузка в CSV.

## Быстрый старт (Docker)

```bash
docker compose up -d --build
```

Откройте <http://localhost:8080>. Демо-аккаунты (создаются при `SEED_DEMO=1`):

| Роль | Email | Пароль |
|---|---|---|
| Преподаватель | `teacher@demo.local` | `teacher123` |
| Студент | `student@demo.local` | `student123` |

Код демо-группы — `DEMO25`, код для регистрации преподавателей задаётся переменной `TEACHER_INVITE`.
Подробности развёртывания, переменные окружения и резервное копирование — в [docs/DEPLOY.md](docs/DEPLOY.md).

Первая сборка образа компилятора скачивает ядро ESP32 и прогревает кэш (≈1 ГБ, 5–10 минут). Если сервер получает
`403` от `downloads.arduino.cc`, соберите образ компилятора на другой машине и перенесите — см.
[docs/DEPLOY.md](docs/DEPLOY.md).

## Разработка

```bash
npm install
npm run dev:server     # API на :8080
npm run dev:web        # Vite на :5173 (проксирует /api и /mqtt)
npm test               # тесты симулятора и валидация всех практик
```

Для компиляции на реальном компиляторе локально запустите сервис: `docker compose up -d compiler mosquitto`.

## Устройство

```
packages/sim       симулятор: лексер, препроцессор, парсер, генератор JS, рантайм (планировщик с виртуальным
                   временем, Arduino API, библиотеки), электрическая модель схемы, сеть, стенд автопроверки
packages/content   курс: модули, 35 практик (сюжет, цели, теория, подсказки, стартовый код и схема,
                   эталонное решение, автопроверки)
apps/web           фронтенд: React + Vite + Tailwind, CodeMirror, редактор схем на SVG
apps/server        API: Fastify + SQLite, проверки в пуле потоков, прокси сети и компилятора, WebSocket к MQTT
compiler           сервис компиляции: arduino-cli + ядро esp32 2.0.17 + библиотеки
mosquitto          конфигурация MQTT-брокера
docs               руководства студента и преподавателя, список практик, развёртывание, устройство, API
```

Пользовательский код транслируется в функции-генераторы JavaScript: `delay()`, HTTP-запросы и ожидание в
FreeRTOS становятся точками `yield`, поэтому симуляция не блокирует браузер, а время в ней виртуальное
(можно ускорять и замедлять). Автопроверки практик выполняются на сервере тем же симулятором в безголовом режиме —
эталонные решения в браузер не попадают.

### Как добавить практику

Читайте [docs/CONTENT_GUIDE.md](docs/CONTENT_GUIDE.md). Коротко: создайте файл в `packages/content/src/practices/`,
зарегистрируйте его в `part-*.ts` и запустите `PRACTICE=<id> npx vitest run` в `packages/content` — тест проверит,
что стартовый код компилируется, эталон проходит все проверки, а стартовый код — нет.
