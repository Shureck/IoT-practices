## packages/sim — симулятор

### Язык: Arduino C++ → JavaScript

`src/lang/` — собственный компилятор подмножества C++, достаточного для скетчей курса:

1. **Лексер и препроцессор** (`lexer.ts`, `preprocess.ts`): `#include`, `#define` с параметрами, `#ifdef`.
2. **Парсер** (`parser.ts`) строит AST: функции, классы и структуры, ссылки, массивы, лямбды, шаблонные типы
   библиотек.
3. **Генератор** (`compiler.ts`) с проверкой типов (`types.ts`) выдаёт JavaScript-модуль с функциями-генераторами.
   Сохраняется семантика C: целочисленное деление, переполнение `int`/`byte`/`uint32_t`, печать `float`
   с двумя знаками, копирование структур, `String`.
4. **Ошибки** — на русском, с подсказками по опечаткам (`suggest`) и словарём известных функций и библиотек
   (`api.ts`, `known.ts`).

`delay()`, сетевые запросы и ожидания FreeRTOS превращаются в `yield`. Каждые ~4096 операций код тоже
уступает управление, поэтому бесконечный `loop()` не вешает браузер.

### Рантайм

* `runtime/machine.ts` — планировщик с **виртуальным временем**: задачи FreeRTOS, прерывания, таймеры,
  отложенные события. Время можно ускорять и замедлять, а проверки идут быстрее реального времени.
* `runtime/core.ts` — Arduino API: GPIO, АЦП, LEDC (API ядер 2.x и 3.x), `pulseIn`, прерывания, таймеры,
  FreeRTOS, регистры GPIO.
* `runtime/libs.ts`, `runtime/netlibs.ts` — библиотеки: Serial, Wire, SPI, DHT, Servo, LiquidCrystal_I2C,
  SSD1306/GFX, NeoPixel, Preferences, Ticker, WiFi, HTTPClient, WebServer, PubSubClient, ArduinoJson.
* Аварии как у настоящей платы — «Guru Meditation» с номером строки.

### Схема

* `circuit/defs.ts` — 25 компонентов: корпус, выводы, свойства. Распиновка ESP32 DevKit V1 (30 выводов)
  совпадает с реальной платой и с Wokwi.
* `circuit/sim.ts` — электрическая модель: цепи (провода, шины макетки) объединяются, затем узловой анализ
  с кусочно-линейной моделью светодиода. Отсюда «сгоревшие» светодиоды, висящие входы, КЗ, перегрузка вывода.
* `circuit/route.ts` — **автоматическая разводка проводов** (см. ниже).

### Сеть

`net/` — виртуальные Wi-Fi-сети, учебные сервисы (`weather.iot`, `chat.iot`, `time.iot`, `station.iot`, `api.iot`,
`facts.iot`), брокер MQTT в памяти для автопроверок. В браузере запросы к внешним адресам идут через прокси сервера,
MQTT — через WebSocket к Mosquitto.

### Автопроверка

`harness.ts` — `Harness` запускает скетч в безголовом режиме, а `CheckContext` даёт проверкам доступ к выводам,
`Serial`, сети и MQTT: «GPIO2 мигает с периодом 1000 мс», «на нажатие печатается ВЫЗОВ!» и т. п.

## Разводка проводов

Провода раскладываются автоматически при каждом изменении схемы.

1. **Выход из вывода.** Для каждого вывода определяется сторона корпуса, к которой он ближе. Провод выходит
   перпендикулярно ей коротким отрезком: из верхнего ряда ESP32 — вверх, из ножек светодиода — вниз,
   из резистора — вбок.
2. **Поиск пути.** A* по сетке 5×5 с учётом направления. Учитываются штрафы:
   * за поворот;
   * за проход над корпусом детали;
   * за проход через чужой вывод и его выводной отрезок;
   * за движение вдоль ряда выводов прямо перед ними — «веерная» зона, чтобы не закрывать подход к соседним
     выводам;
   * за наложение на провод другой цепи и за пересечение.
3. **Порядок.** Сначала прокладываются короткие провода, остальные их обходят и расходятся по соседним дорожкам.
4. **Общие шины.** Провода одной цепи (GND, питание) охотно идут общей линией. Там, где они расходятся,
   рисуется точка-узел.
5. **Ручная правка.** Точки, добавленные двойным кликом или при прокладке, обязательны: путь строится через них
   по порядку.

Разводка схемы самой большой практики занимает 15–40 мс. Качество проверяет тест
`packages/content/test/routing.test.ts` на схемах всех практик: нет наложений разных цепей, нет проходов через
чужие выводы, только ортогональные отрезки.

## packages/content — курс

Модули, достижения, сюжет (`modules.ts`) и 35 практик (`practices/*.ts`). Практика содержит:
* сюжет, цели, теорию и подсказки;
* стартовые код и схему, эталонное решение;
* автопроверки — функции над `CheckContext`.

Тест `content.test.ts` для каждой практики проверяет, что стартовый код компилируется, эталон проходит все проверки,
а стартовый код — нет. Руководство автора — [CONTENT_GUIDE.md](CONTENT_GUIDE.md).

`publicPractice()` убирает из практики эталон и проверки — в браузер уходит только публичная часть.

## apps/server — API

* **Fastify 5 + better-sqlite3.** Схема и миграции — `db.ts`. Сессия — JWT в httpOnly-cookie `sid`.
* **Роли:** студент и преподаватель (по коду `TEACHER_INVITE`), группы с кодами приглашения.
* **Проверки** — `pool.ts` и `check-worker.ts`: пул `worker_threads` с таймаутом, зависший скетч не блокирует сервер.
* **Начисление** — `grading.ts`: опыт за первую успешную сдачу, минус 10 % за подсказку, не ниже половины;
  достижения.
* **Сеть** — `net.ts`: прокси HTTP-запросов скетчей с защитой от SSRF (запрет приватных адресов, лимиты размера
  и времени); WebSocket-прокси к Mosquitto.
* **Компиляция** — прокси к сервису `compiler`, только для вошедших пользователей.

Контракт API — [API.md](API.md).

## compiler — настоящая сборка

`compiler/server.mjs` — небольшой HTTP-сервис: `POST /compile {code}` → `{ok, log, ms, binaries[]}`.
* Внутри: `arduino-cli`, ядро `esp32:esp32@2.0.17` (как на лекциях), библиотеки курса, прогретый кэш сборки.
* Число параллельных сборок задаёт `SLOTS`, остальные ждут в очереди.
* `#include` с абсолютным путём или выходом из каталога скетча (`..`) отклоняется.

Браузер прошивает полученные `.bin` через Web Serial и `esptool-js` — нужен HTTPS (или `localhost`).

## Безопасность

* Эталонные решения и проверки выполняются только на сервере; тест `auth.test.ts` следит, чтобы их не было в ответах API.
* Пароли — bcrypt; ограничения частоты для входа, проверок и сдач.
* Скетч на сервере — это JS, сгенерированный нашим транслятором (а не произвольный код пользователя); он выполняется
  в отдельном worker-потоке с таймаутом, зависание не блокирует сервер.
* MQTT-брокер учебный, без авторизации — не передавайте через него ничего секретного.
