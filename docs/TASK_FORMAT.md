# Справочник по файлу задачи ESP32 Lab

Формат: `esp32lab-task/1`. Файл — YAML (годится и JSON). Этот справочник собирается из кода симулятора и всегда соответствует тому, что умеет сайт.

## 1. Как создать задачу

1. Скачайте пример («Пример задачи») и скопируйте его.
2. Поменяйте поля, схему, эталонное решение и проверки.
3. Загрузите файл во вкладке «Задачи» — сайт проверит формат, прогонит эталон через проверки и покажет ошибки с номерами строк.
4. Если всё зелёное — нажмите «Опубликовать». Новая задача появится в курсе; откройте её группе во вкладке «Доступ».

Чтобы поправить задачу, нажмите «Изменить»: откроется её файл. Для встроенных задач меняется только описание (тексты, код, схема, баллы); их автопроверки остаются прежними (`checks: builtin`), пока вы не опишете свои. «Вернуть встроенную» снимает все правки.

**Про YAML.** Отступы — пробелы (не табы). Многострочный текст и код пишут после `|` с отступом. Текст, в котором есть «: » (двоеточие с пробелом) или который начинается со знака `[`, `{`, `*`, `&`, `#`, берите в кавычки: `title: "Задача: часть 1"`. Внутри списка в `[ ]` текст с запятой тоже берут в кавычки. Комментарии — от `#`.

## 3. Схема

```yaml
starterCircuit:
  parts:
    - { id: led1, type: led, x: 330, y: -40, props: { color: green } }
    - { id: r1, type: resistor, x: 300, y: 150, props: { value: 220 } }
  wires:
    - esp:D25 r1:1 green                # "откуда куда [цвет]"
    - { from: r1:2, to: led1:A, color: green, via: [[320, 100]] }   # с точками изгиба
```

- Плата ESP32 (`id: esp`) добавляется автоматически — в `parts` её не пишут. Провода к ней: `esp:D25`, `esp:GND.1`.
- Деталь: `id` (латиница, цифры, «_»), `type` (из таблицы ниже), `x`, `y` — положение **первого** вывода, `rot` — поворот 0/90/180/270, `props` — свойства, `locked` — можно ли двигать студенту (по умолчанию true).
- Конец провода: `деталь:вывод`. Цвет — слово (`green`, `red`, `black`, `yellow`, `blue`, `orange`) или `#rrggbb`; по умолчанию `green`.
- Плата стоит в (0, 0) и занимает 220×100. Детали удобно ставить над платой (y от −40 до −80) или правее (x ≥ 280).

## 4. Детали

Значения свойств в `props` проверяются. Свойства с пометкой «ручка» студент крутит во время симуляции; проверки умеют их менять шагом `set`.

### Плата
#### ESP32 DevKit V1 — `esp32`

Плата с микроконтроллером ESP32: 240 МГц, Wi-Fi, Bluetooth. Встроенный синий светодиод на GPIO2.

Выводы — в таблице «Плата ESP32» ниже.

Свойств нет.

#### Макетная плата — `breadboard`

Беспаечная макетка: отверстия в столбике из 5 соединены между собой, длинные линии по краям — шины питания.

Выводы: `a1`…`j30` (30 столбцов, ряды a–e соединены между собой в каждом столбце, f–j — тоже) и четыре шины питания `tn1`…`tn30`, `tp1`…`tp30`, `bp1`…`bp30`, `bn1`…`bn30` (без каждого 6-го отверстия). Деталь можно воткнуть в макетку, совместив координаты выводов.

Свойств нет.

## 5. Автопроверки

Проверка — это список **шагов**. Шаги выполняются по порядку над симулированной платой; когда нужно проверить результат — шаг `expect` с **условием**. Всё время — в миллисекундах виртуального времени, поэтому проверка на 60 с идёт за секунды.

```yaml
checks:
  - id: follow                      # короткий id: латиница, цифры, «-»
    title: Светодиод горит, пока кнопка нажата   # так проверку видит студент
    timeoutMs: 20000                # (необязательно) лимит реального времени, 1000–60000
    steps:
      - wait: 1500
      - hold: { part: btn }
      - waitFor: { ledOn: led1 }
        timeout: 1500
        message: Нажали кнопку — светодиод не загорелся
```

- У каждого шага одно основное действие; рядом могут стоять дополнительные поля (`message`, `timeout`, `for`…).
- **Сообщение при неудаче.** У условий есть понятный текст по умолчанию; своё `message` лучше писать там, где можно подсказать студенту, что делать.
- **Метки.** Шаг `mark: t0` запоминает момент и позицию в Serial. Дальше: время `t0+500`, `since: t0`.
- **Время.** Число (мс от запуска), `now`, `now-3000`, `имя_метки`, `имя_метки+500`.
- **Вывод GPIO.** Число (`25`), `D25`, `GPIO25`, `near:led1.A` (GPIO, к которому подключён вывод детали, напрямую или через резистор — не зависит от того, какой номер выбрал студент), `at:led1.A` (только напрямую).
- **Устойчивость.** Перед каждой проверкой «ручки» датчиков возвращаются в положение из эталонной/стартовой схемы — положение, оставленное студентом, проверку не ломает.

### Шаги

#### `wait`

Дать симуляции поработать столько-то миллисекунд виртуального времени.

Значение: число.

```yaml
- wait: 1500
```

#### `until`

Работать до абсолютного момента (если он уже прошёл — ничего не делать).

Значение: время, мс: число или `now`, `now-3000`, `метка+500`.

```yaml
- until: t0+9300
```

#### `set`

Выставить свойство детали — как поворот ручки датчика: освещённость, положение потенциометра, расстояние, температуру…

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `part` | id детали со схемы | да | Деталь |
| `prop` | текст | да | Свойство (из таблицы деталей) |
| `value` | число, true/false или текст | да | Значение: число, true/false или текст |

```yaml
- set: { part: ldr, prop: lux, value: 2000 }
```

#### `press`

Нажать и отпустить кнопку: держать `ms` мс, затем (необязательно) подождать `after` мс.

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `part` | id детали со схемы (тип: button) | да | Кнопка |
| `ms` | число | нет (по умолч. 200) | Сколько держать, мс |
| `after` | число | нет (по умолч. 0) | Пауза после, мс |

```yaml
- press: { part: btn, ms: 300 }
```

#### `pressSeq`

Нажать несколько кнопок по очереди (кодовая клавиатура).

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `parts` | список: id детали со схемы (тип: button) | да | Кнопки по порядку |
| `ms` | число | нет (по умолч. 150) | Сколько держать каждую, мс |
| `gap` | число | нет (по умолч. 250) | Пауза между нажатиями, мс |

```yaml
- pressSeq: { parts: [b1, b2, b3, b4], ms: 150, gap: 250 }
```

#### `hold`

Зажать кнопку (`on: true`, по умолчанию) или отпустить (`on: false`) — не ждёт, время идёт в следующих шагах.

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `part` | id детали со схемы (тип: button) | да | Кнопка |
| `on` | true / false | нет (по умолч. true) | Зажать |

```yaml
- hold: { part: btn, on: true }
```

#### `motion`

Сработал датчик движения (PIR).

Значение: id детали со схемы (тип: pir).

```yaml
- motion: pir
```

#### `send`

Отправить текст в Serial программе (как из монитора порта). `\n` — перевод строки.

Значение: текст.

```yaml
- send: "KEY?\n"
```

#### `mqttPublish`

Опубликовать MQTT-сообщение «от внешнего мира» (программа должна быть на него подписана).

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `topic` | текст | да | Тема |
| `payload` | текст | да | Сообщение |
| `retain` | true / false | нет (по умолч. false) | Retained |

```yaml
- mqttPublish: { topic: "station/cmd", payload: "on" }
```

#### `mark`

Запомнить текущий момент и позицию в выводе Serial под именем — дальше на метку можно ссылаться: время `имя+500`, `since: имя`.

Значение: имя новой метки.

```yaml
- mark: t0
```

#### `expect`

Проверить условие прямо сейчас; если не выполнено — проверка провалена.

Значение: условие.

Дополнительные поля рядом с шагом:

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `message` | текст | нет | Своё сообщение при неудаче (если не задано — понятный текст по умолчанию) |

```yaml
- expect: { ledOn: led1 }
  message: "Нажали кнопку — светодиод не загорелся"
```

#### `waitFor`

Ждать, пока условие станет верным (проверяется каждые `step` мс), но не дольше `timeout` мс; не дождались — проверка провалена.

Значение: условие.

Дополнительные поля рядом с шагом:

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `timeout` | число | нет (по умолч. 2000) | Сколько ждать, мс |
| `step` | число | нет (по умолч. 10) | Как часто проверять, мс |
| `as` | имя новой метки | нет | Поставить метку в момент, когда условие выполнилось |
| `message` | текст | нет | Своё сообщение при неудаче (если не задано — понятный текст по умолчанию) |

```yaml
- waitFor: { relay: relay1 }
  timeout: 1000
  as: opened
```

#### `always`

Условие должно быть верным всё время в течение `for` мс (проверяется каждые `step` мс). Например, «светодиод горит ровно, без мигания».

Значение: условие.

Дополнительные поля рядом с шагом:

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `for` | число | да | Как долго, мс |
| `step` | число | нет (по умолч. 20) | Как часто проверять, мс |
| `message` | текст | нет | Своё сообщение при неудаче (если не задано — понятный текст по умолчанию) |

```yaml
- always: { ledOn: led1 }
  for: 2000
```

#### `never`

Условие не должно выполниться ни разу в течение `for` мс. Например, «зелёный и красный никогда не горят вместе».

Значение: условие.

Дополнительные поля рядом с шагом:

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `for` | число | да | Как долго, мс |
| `step` | число | нет (по умолч. 20) | Как часто проверять, мс |
| `message` | текст | нет | Своё сообщение при неудаче (если не задано — понятный текст по умолчанию) |

```yaml
- never: { all: [ { ledOn: red }, { ledOn: green } ] }
  for: 60000
  message: "Опасно: красный и зелёный вместе"
```

#### `repeat`

Повторить вложенные шаги несколько раз.

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `times` | целое число | да | Сколько раз |
| `steps` | список шагов | да | Шаги |

```yaml
- repeat:
    times: 3
    steps:
      - press: { part: btn }
      - wait: 500
```

#### `if`

Выполнить разные шаги в зависимости от условия.

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `cond` | условие | да | Условие |
| `then` | список шагов | да | Если верно |
| `else` | список шагов | нет | Если нет |

```yaml
- if:
    cond: { ledOn: led1 }
    then:
      - wait: 100
    else:
      - fail: "Светодиод не горит"
```

#### `fail`

Провалить проверку с сообщением (обычно внутри `if`).

Значение: текст.

```yaml
- fail: "Так делать нельзя"
```

#### `load`

#### `lcd`

| `part` | id детали со схемы | да | Деталь |
| `pin` | имя вывода детали (из таблицы деталей) | да | Вывод детали |
| `to` | `gpio` · `gpio-direct` · `gnd` · `gnd-via-resistor` · `3v3` · `vin` | да | Куда подключён |
| `gpio` | GPIO: число, `D25`, `GPIO25`, `near:led1.A` (вывод детали, напрямую или через резистор) или `at:led1.A` (напрямую) | нет | Конкретный GPIO (для to: gpio / gpio-direct) |

```yaml
{ wired: { part: led1, pin: C, to: gnd-via-resistor } }
```

#### `ledWiring`

Светодиод подключён правильно: анод через резистор к GPIO, катод на GND.

Значение: id детали со схемы (тип: led).

```yaml
{ ledWiring: led1 }
```

#### `codeUses`

Код студента (без комментариев) содержит выражение. Регистр важен.

Значение: регулярное выражение (JS).

```yaml
{ codeUses: "\\bdelay\\s*\\(" }
```

#### `codeNotUses`

Код студента (без комментариев) НЕ содержит выражение.

Значение: регулярное выражение (JS).

```yaml
{ codeNotUses: "\\bdelay\\s*\\(10000" }
```

#### `http`

Программа отправила HTTP-запрос: адрес содержит текст (`urlContains`, без учёта регистра) или подходит под выражение (`urlMatches`), метод — `method`.

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `urlContains` | текст | нет | Адрес содержит |
| `urlMatches` | регулярное выражение (JS) | нет | Адрес подходит под выражение |
| `method` | текст | нет | Метод (GET, POST…) |
| `count` | число или диапазон `[от, до]` | нет | Сколько раз: число (ровно) или диапазон [от, до] |

```yaml
{ http: { urlContains: "api.open-meteo.com", method: GET } }
```

#### `mqtt`

Программа опубликовала MQTT-сообщение: тема подходит под фильтр (`topic`, поддерживаются `+` и `#`), текст сообщения содержит `payloadContains`.

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `topic` | текст | нет (по умолч. #) | Фильтр темы |
| `payloadContains` | текст | нет | Сообщение содержит |
| `count` | число или диапазон `[от, до]` | нет | Сколько раз: число (ровно) или диапазон [от, до] |

```yaml
{ mqtt: { topic: "station/+/temp", payloadContains: "21" } }
```

#### `warnings`

Предупреждения симулятора («светодиод сгорел», «вывод перегружен»…): `none: true` — их нет; `contains` — есть предупреждение с этим текстом.

| Поле | Значение | Обяз. | Описание |
|---|---|---|---|
| `none` | true / false | нет | Предупреждений нет |
| `contains` | текст | нет | Есть предупреждение с текстом |

```yaml
{ warnings: { none: true } }
```

### Типичные рисунки проверок

**Схема собрана**: `expect: { ledWiring: led1 }`, `expect: { wired: { part: btn, pin: 1, to: 3v3 } }`.

**Реакция на кнопку**: `hold` → `waitFor: { ledOn: … }` → `hold … on: false` → `waitFor: { ledOff: … }`.

**Мигание**: `wait: 8200` → `expect: { period: { pin: near:led1.A, from: 0, to: 8200, ms: 2000, tol: 60 } }`.

**Датчик**: `set: { part: ldr, prop: lux, value: 2 }` → `wait` → `expect: …`.

**«Никогда не должно быть»**: `never: { all: [ … ] }` с `for: 60000`.

**Печать один раз на событие**: `mark: t0` → `press` → `expect: { serial: { contains: …, since: t0, count: 1 } }`.

## 7. HTTP-маршруты для проверок (`httpRoutes`)

Во время проверки программа студента ходит в «интернет», которого нет. Маршруты отвечают вместо него:

```yaml
httpRoutes:
  - urlContains: api.example.org/weather
    method: GET            # необязательно
    status: 200            # по умолчанию 200
    body: { temp: 21.5 }   # объект станет JSON; можно и строку
```

Поля: `urlContains` или `urlMatches` (одно из двух), `method`, `status`, `contentType`, `body`. Что программа запросила — проверяется условием `http`; MQTT — условием `mqtt` и шагом `mqttPublish`.

## 8. Что проверяется при публикации

1. Формат: все поля, типы значений, детали и выводы существуют, провода ведут к настоящим выводам, у условий и шагов верные поля.
2. Эталонный код компилируется.
3. Эталонное решение (с его схемой) проходит **все** проверки.
4. Стартовый код проходит **не все** проверки (иначе задача решена «из коробки»).

Если что-то из этого не выполнено, публикация заблокирована, а причина показана с номером строки. Предыдущие версии задачи сохраняются в «Истории» — к любой можно вернуться.

## 9. Язык программ: что умеет симулятор

Студент пишет обычный Arduino C++ для ESP32. Ниже — всё, что поддерживает симулятор.

#### 🔌 Цифровые выводы

- `pinMode(pin, mode)` — Настраивает вывод: OUTPUT — выход, INPUT — вход, INPUT_PULLUP / INPUT_PULLDOWN — вход со встроенной подтяжкой к 3,3 В / к земле.
- `digitalWrite(pin, HIGH|LOW)` — Подаёт на выход 3,3 В (HIGH) или 0 В (LOW). Вывод должен быть настроен как OUTPUT.
- `int digitalRead(pin)` — Читает логический уровень на входе: HIGH (1) или LOW (0). Без подтяжки неподключённый вход «висит» и даёт случайные значения.
- `attachInterrupt(digitalPinToInterrupt(pin), isr, RISING|FALLING|CHANGE)` — Вызывает функцию-обработчик при изменении уровня на выводе. Обработчик должен быть коротким, без delay(); общие переменные объявляйте volatile.
- `detachInterrupt(pin)` — Отключает прерывание на выводе.

#### 📈 Аналоговые входы и ШИМ

- `uint16_t analogRead(pin)` — Читает напряжение 0…3,3 В как число 0…4095 (12 бит). Выводы АЦП1: 32–39; АЦП2 (0, 2, 4, 12–15, 25–27) не работает вместе с Wi-Fi.
- `uint32_t analogReadMilliVolts(pin)` — Напряжение на входе в милливольтах.
- `analogReadResolution(bits)` — Разрешение АЦП: 9–12 бит.
- `analogWrite(pin, 0…255)` — ШИМ-сигнал с заполнением value/255 (частота 1 кГц). Удобный способ менять яркость светодиода.
- `ledcSetup(channel, freq, resolution)` — Ядро 2.x: настраивает канал ШИМ (0–15): частоту в Гц и разрешение в битах (1–20). freq × 2^bits не должно превышать 80 МГц.
- `ledcAttachPin(pin, channel)` — Ядро 2.x: подключает вывод к каналу ШИМ.
- `ledcWrite(channel, duty)` — Задаёт заполнение ШИМ: 0…2^bits − 1. В ядре 3.x первым аргументом передаётся номер вывода.
- `ledcAttach(pin, freq, resolution)` — Ядро 3.x: подключает вывод к ШИМ одной командой.
- `ledcWriteTone(channel, freq)` — Меандр заданной частоты (для пассивной пищалки).
- `tone(pin, freq, [duration])` — Звук на пассивной пищалке. Без duration звучит до noTone(pin).
- `noTone(pin)` — Выключает звук.
- `dacWrite(25|26, 0…255)` — Настоящее аналоговое напряжение 0…3,3 В на ЦАП (только GPIO25 и GPIO26).
- `long map(x, inMin, inMax, outMin, outMax)` — Пересчитывает число из одного диапазона в другой (целочисленно).
- `constrain(x, low, high)` — Ограничивает значение диапазоном.

#### ⏱️ Время

- `delay(ms)` — Пауза в миллисекундах. Пока идёт delay, loop() стоит — для нескольких одновременных дел используйте millis().
- `delayMicroseconds(us)` — Короткая пауза в микросекундах (например, импульс 10 мкс для HC-SR04).
- `unsigned long millis()` — Миллисекунды с момента включения. Основа «неблокирующих» таймеров.
- `unsigned long micros()` — Микросекунды с момента включения.
- `unsigned long pulseIn(pin, HIGH|LOW, [timeout])` — Измеряет длительность импульса в мкс (по умолчанию ждёт до 1 с).
- `hw_timer_t* timerBegin(num, divider, countUp)` — Ядро 2.x: аппаратный таймер (0–3). Делитель 80 → 1 тик = 1 мкс. В ядре 3.x: timerBegin(частота_Гц).
- `timerAttachInterrupt(timer, isr, edge)` — Обработчик срабатывания таймера.
- `timerAlarmWrite(timer, ticks, autoreload)` — Через сколько тиков срабатывать и повторять ли.
- `timerAlarmEnable(timer)` — Запускает срабатывания таймера.

#### 💬 Serial (UART)

- `Serial.begin(baud)` — Открывает порт. Скорость должна совпадать со скоростью монитора порта (обычно 115200).
- `Serial.print(value, [format])` — Печатает значение без перевода строки. float — с 2 знаками (или Serial.print(x, 3)); целые — DEC/HEX/BIN.
- `Serial.println(value)` — Печатает значение и переводит строку.
- `Serial.printf(fmt, ...)` — Форматированный вывод: %d, %u, %.2f, %s (для String — .c_str()), %x.
- `int Serial.available()` — Сколько байт пришло и ждёт чтения.
- `String Serial.readStringUntil('\n')` — Читает строку до символа (или до тайм-аута 1 с).
- `Serial2.begin(baud, SERIAL_8N1, RX, TX)` — Второй аппаратный UART. По умолчанию RX = 16, TX = 17. Соединяйте TX одного устройства с RX другого.

#### 🔤 Строки

- `String s = "текст";` — Удобная строка Arduino: склейка через +, методы length(), indexOf(), substring(), toInt(), toFloat(), trim(), equals().
- `sprintf(buf, fmt, ...)` — Форматирует текст в массив char. Следите за размером буфера!
- `int strcmp(a, b)` — Сравнивает две C-строки: 0 — равны. Для const char* нельзя использовать ==.
- `int atoi(str)` — Строку в целое число.

#### 📶 Wi-Fi и HTTP

- `WiFi.begin(ssid, password)` — Подключение к точке доступа. Дождитесь WiFi.status() == WL_CONNECTED.
- `int WiFi.scanNetworks()` — Сканирует эфир; дальше WiFi.SSID(i), WiFi.RSSI(i).
- `WiFi.softAP(ssid, pass)` — Режим точки доступа: ESP32 сам создаёт сеть (IP 192.168.4.1).
- `http.begin(url)` — Подготовка запроса. Затем http.GET() или http.POST(body) возвращает код ответа.
- `http.addHeader(name, value)` — Заголовок запроса, например Content-Type: application/json.
- `DeserializationError deserializeJson(doc, input)` — Разбирает JSON в документ ArduinoJson. Доступ: doc["key"], doc["arr"][0]["x"]; значение по умолчанию: doc["x"] \| 0.
- `serializeJson(doc, output)` — Превращает документ в JSON-строку (String, массив char или Serial).
- `server.on(path, handler)` — Веб-сервер на ESP32: обработчик пути. В loop() обязательно server.handleClient().

#### 🛰️ MQTT (PubSubClient)

- `mqtt.setServer(host, 1883)` — Адрес брокера. В симуляторе: mqtt.iot (или broker.hivemq.com).
- `bool mqtt.connect(clientId, [user, pass], [willTopic, qos, retain, willMsg])` — Подключение к брокеру. clientId должен быть уникальным. LWT — «завещание», публикуется брокером при обрыве связи.
- `bool mqtt.publish(topic, payload, [retain])` — Публикация сообщения. Размер пакета ограничен буфером 256 байт (setBufferSize).
- `bool mqtt.subscribe(filter)` — Подписка: + — один уровень, # — все уровни ниже (только в конце).
- `bool mqtt.loop()` — Обрабатывает входящие сообщения и поддерживает соединение — вызывайте в каждом loop().
- `mqtt.setCallback(fn)` — Функция void cb(char* topic, byte* payload, unsigned int length) для входящих сообщений.

#### 🌡️ Датчики и модули

- `float dht.readTemperature()` — Температура (°C) с DHT11/DHT22. nan — датчик не отвечает. Чаще раза в 2 с не опрашивать.
- `float dht.readHumidity()` — Относительная влажность, %.
- `servo.write(angle)` — Поворот сервопривода на угол 0–180° (библиотека ESP32Servo; сначала servo.attach(pin)).
- `lcd.print(value)` — Вывод на символьный дисплей. Перед этим lcd.init(); lcd.backlight(); lcd.setCursor(col, row);
- `strip.setPixelColor(i, r, g, b)` — Цвет светодиода ленты; применить — strip.show().
- `prefs.putInt(key, value)` — Сохраняет число во флеш (переживает перезагрузку). Сначала prefs.begin("имя").

#### 🧵 FreeRTOS

- `xTaskCreate(fn, "имя", stack, param, priority, &handle)` — Запускает функцию как отдельную задачу. Задача — бесконечный цикл с vTaskDelay внутри.
- `vTaskDelay(ticks)` — Пауза задачи (1 тик = 1 мс); другие задачи в это время работают.
- `QueueHandle_t xQueueCreate(len, itemSize)` — Очередь для передачи данных между задачами: xQueueSend / xQueueReceive.
- `SemaphoreHandle_t xSemaphoreCreateMutex()` — Мьютекс для защиты общего ресурса: xSemaphoreTake / xSemaphoreGive.
